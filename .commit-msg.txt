Fix crash and black screen in dynamic tile renderer — 3 critical bugs

Bug 1: Crash — makeCurrent() called from network callback
  requestTile() created OpenGL textures in the QNetworkReply::finished
  callback, which runs on the network thread, not the GL thread.
  Calling makeCurrent() there crashes Qt's OpenGL context.
  Fix: Store downloaded image as pendingImage in the tile struct.
  Upload as GL texture in drawMapBackground() (GL thread) instead.

Bug 2: Crash — dangling pointer to pruned tile
  If pruneInvisibleTiles() removed a tile while its network reply
  was in-flight, the rawPtr in the lambda became dangling.
  Fix: Check if tile still exists in m_mapTiles before using it
  in the network callback.

Bug 3: Black screen — UpdateMapTiles called before widget visible
  SetMapCenter() called UpdateMapTiles() during construction when
  width()/height() were 0, causing division by zero and no tiles.
  Fix: Don't call UpdateMapTiles from SetMapCenter. Set m_lastCameraZ
  = -1 to force tile update on next paintGL when widget is visible.
  Added width/height guard in UpdateMapTiles.

Bug 4: Infinite recursion in UpdateMapTiles
  When zoom level changed, UpdateMapTiles called itself recursively.
  Fix: Inline the zoom reduction logic without recursion.

Also: ClearMapBackground no longer calls makeCurrent (just clears
the vector, unique_ptr handles texture cleanup).
