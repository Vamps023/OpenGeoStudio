Fix GPXZ crash: handle tiled (Cloud Optimized) GeoTIFFs in DemDecoder

Root cause: GPXZ returns Cloud Optimized GeoTIFF (COG) which uses
TIFF tiles, not scanlines. The previous decodeGeoTiff used
TIFFReadScanline exclusively, which crashes on tiled TIFFs because:
  1. The scanline buffer size is wrong for tiled data
  2. TIFFReadScanline returns -1 for tiled images
  3. The buffer access causes a segfault

Fix: Rewrote decodeGeoTiff to handle both layouts:
  - TIFFIsTiled() check determines the layout
  - Tiled: uses TIFFReadTile with TIFFTileSize buffer, copies
    pixels tile-by-tile into the output grid
  - Stripped: uses TIFFReadScanline with TIFFScanlineSize buffer
    (also fixes buffer size to match libtiff's expectation)

Additional fixes:
  - Unified data type handling via readPixelAsFloat lambda — supports
    Float32, Float64, Int16, Int32, UInt8, UInt16, UInt32 in one path
  - Uses TIFFScanlineSize/TIFFTileSize for correct buffer allocation
    (was using width*sizeof(float) which is wrong for non-float data)
  - Added safety guards in resample() for invalid/empty source tiles
  - Added empty data check at start of decodeGeoTiff
