Phase 4e: Road engine integration — centerline sampling, edges, lane boundaries, mesh

Added RoadEngineService that calls the C++ road engine directly
(no IPC, no N-API, no Node.js):

- sampleCenterline: Uses geo::Road::sampleCenterline() member function
  for proper bezier/arc/line sampling
- sampleLeftEdge/sampleRightEdge: Computed from centerline + width offset
  (the free functions are declared but not implemented in the engine)
- generateLaneBoundaries: Uses geo::generateLaneBoundaries() from mesh.hpp
- generateMesh: Uses geo::generateRoadMesh() from mesh.hpp
- exportOpenDrive: Stub for now (opendrive.hpp has include conflicts)

Updated RoadViewport2D::drawRoad to use the engine:
- Centerline is now sampled by the C++ engine (64 samples)
- Left/right edges are drawn in red/blue
- Lane boundaries are drawn as white dashed lines for multi-lane roads
- Fallback to straight line if engine sampling fails

Note: The public road_engine.hpp declares free functions like
geo::sampleCenterline(const Road&, int) but only the member function
Road::sampleCenterline(int) is implemented. The service uses the
member function. This is a known issue with the header-only engine's
API structure.
