Phase 2.6: Road Mark Generator — semantic marking descriptions

Introduces the road mark generation layer that transforms LaneNetwork
boundaries into structured marking descriptions. No mesh, no rendering
— only logical marking data with parametric dash representation.

New file: road_mark_generator.hpp
  Separation of concerns:
    lane_engine.hpp         = Data model
    lane_geometry.hpp       = Evaluation
    lane_sampling.hpp       = Sampling
    lane_network.hpp        = Persistent lane network
    road_mark_generator.hpp = Mark generation (THIS FILE)

  DashPattern struct:
    - dashLength, gapLength, phase
    - period() = dash + gap
    - isDashAt(distance) — parametric dash placement
    - Default: 3m dash, 9m gap (MUTCD broken line)

  RoadMarkStyle struct:
    - type (LaneRoadMarkType), color, width
    - dashPattern (for dashed types)
    - isDashed(), isSolid(), isDouble() queries

  RoadMarkPolyline struct:
    - style, innerLaneId, outerLaneId
    - isRoadEdge, isCenterLine flags
    - startS, endS, length
    - vector<SamplePoint> samples (from LaneBoundary)
    - id() debug string

  RoadMarkNetwork struct:
    - vector<RoadMarkPolyline> markings
    - findByType(), centerMarks(), edgeMarks()
    - dashedMarks(), solidMarks() queries

  RoadMarkLibrary:
    - Maps boundary roles to styles
    - Default: MUTCD (center=dashed yellow, inner=dashed white, edge=solid white)
    - european() — white center
    - none() — no markings

  generateRoadMarks(network, library):
    - Transforms LaneBoundary → RoadMarkPolyline
    - One source of truth: LaneNetwork provides geometry, library provides style
    - Skips None-type markings
    - No geometry recomputation

  generateDashedSegments(mark):
    - Returns (startDist, endDist) pairs for each dash
    - Parametric — no tiny line segments
    - Mesh generator (2.7) will tessellate from these
