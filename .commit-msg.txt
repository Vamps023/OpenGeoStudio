Rewrite map rendering to QGIS-style composite approach

Studied QGIS's map rendering architecture (qgstiledownloadmanager.cpp,
qgstilecache.cpp, qgsmapcanvas.cpp) and adopted their simpler approach:

OLD (broken):
  - Per-tile OpenGL textures created in drawMapBackground
  - Multiple texture objects, multiple draw calls
  - Per-tile VBO updates per frame
  - Fragile texture lifetime management
  - Tiles pruned incorrectly, textures lost

NEW (QGIS-inspired):
  - Download tiles as QImage (network thread) — same as before
  - Composite ALL tiles into a single QImage using QPainter
    (like QGIS composites layers into QgsMapCanvasMap image)
  - Upload that single QImage as ONE OpenGL texture
  - Draw ONE quad with that texture
  - Only recomposite when tiles change (dirty flag)

This eliminates:
  - Per-tile OpenGL texture creation/management
  - Per-tile VBO updates
  - Multiple draw calls
  - Texture lifetime issues
  - Pruning-related texture loss

Files changed:
  - map_view_gl.h — removed per-tile texture, added composite
    texture + composite image + world bounds
  - map_view_gl.cpp — rewrote drawMapBackground to composite
    and draw single texture; added compositeMapImage()
