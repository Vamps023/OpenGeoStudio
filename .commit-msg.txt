Phase 2.4: Lane boundary & centerline sampling

Introduces the sampling layer that converts lane evaluation (2.3)
into polylines with adaptive refinement. First production feature
— produces visible output (polylines) from the lane engine.

New file: lane_sampling.hpp
  Separation of concerns:
    lane_engine.hpp   = Data model
    lane_geometry.hpp = Evaluation (single point)
    lane_sampling.hpp = Sampling (polyline generation)

  SamplePoint struct:
    - position (Point2D): world-space x, y
    - s: arc-length along reference line (for UV, OpenDRIVE)
    - heading: heading angle (for lane markings, debug)
    - laneOffset: lateral offset (for mesh generation)

  LanePolyline struct:
    - laneId, isBoundary, isOuter metadata
    - vector<SamplePoint> points
    - positions() convenience accessor
    - length() total polyline length

  SamplingParams:
    - maxError: 0.25m chord error tolerance
    - maxSpacing: 10m maximum spacing between samples
    - minSamples, maxSamples bounds

  Functions:
    - sampleLaneCenter(road, laneId, params): lane centerline polyline
    - sampleLaneBoundary(road, laneId, outer, params): lane edge polyline
    - sampleAllBoundaries(road, params): all lane boundaries
    - sampleAllCenterlines(road, params): all lane centerlines

  Adaptive sampling:
    - Curvature-based recursive midpoint displacement
    - More samples in high-curvature regions (arcs, spirals, bezier)
    - Fewer samples in straight regions
    - maxSpacing ensures minimum sampling density
    - Reuses Phase 1 sampleAdaptive philosophy
