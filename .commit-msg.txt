Unify project save workflow: terrain + roads + 3D studio under one .ogproj

Previously each studio saved data independently:
  - Terrain Studio: state was in a local TerrainStore, never persisted
  - Road Studio: LaneMaker saved .xodr files via its own dialog, no link to project
  - 3D Studio: exports to hardcoded paths, no project connection

Now all studios share the same project file (.ogproj):

Save (File > Save Project or Ctrl+S):
  1. TerrainStore.toJson() → serialized into project.moduleState["terrain"]
     (bounds, tile grid, export settings, selected tiles, API keys)
  2. LaneMaker's last saved .xodr path → project.moduleState["road-studio"]["xodrFile"]
  3. Project bounds updated from terrain bounds
  4. Single .ogproj file written with all module state

Open (File > Open Project):
  1. .ogproj loaded → moduleState parsed
  2. TerrainStore.fromJson() restores bounds, tiles, export settings
  3. Road .xodr file path restored (user can load it in LaneMaker)
  4. Project bounds synced to terrain store

Architecture changes:
  - TerrainStore moved from TerrainStudioWidget-local to ApplicationContext
    (shared singleton, accessible from all studios)
  - LaneMaker MainWindow::saveToFile/loadFromFile now set
    setProperty("lastRoadFile", path) so the project system can track it
  - 3D Studio export functions now read from project basePath/Terrain
    and basePath/Roads (matching ProjectManager::kSubfolders casing)
  - saveProjectState() and loadProjectState() methods in AppMainWindow
    handle the full serialization round-trip

Project folder structure (unchanged, now actually used):
  MyProject/
    MyProject.ogproj       ← all module state saved here
    Terrain/               ← terrain TIFF/PNG exports
    Roads/                 ← road .xodr files
    Exports/               ← 3D studio exports
    Scene/                 ← scene files
    ...
