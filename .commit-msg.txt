Fix Unicode path crash in GeoTIFF export (OneDrive/Chinese folders)

libtiff's TIFFOpen uses fopen() on Windows, which cannot handle
Unicode paths (e.g. Chinese characters in OneDrive folder names
like Documents/文档/OpenGeoStudio/...).

Fix: new PathHelper utility converts Unicode paths to Windows 8.3
short paths (GetShortPathNameW) before passing to TIFFOpen.
Short paths are ASCII-safe and work with fopen().

Example:
  Input:  C:\Users\nares\OneDrive\文档\OpenGeoStudio\Projects\Test\Terrain\...
  Output: C:\Users\nares\OneDrive\73EC~1\OPENGE~1\Projects\Test\Terrain\...

Files fixed (all TIFFOpen calls):
  - RasterWriter.cpp (2 calls — main GeoTIFF writer)
  - ExportEngine.cpp (3 calls — legacy GeoTIFF writer)
  - DemDecoder.hpp (1 call — reading downloaded DEM tiles)

PathHelper.hpp:
  - NOMINMAX defined to prevent windows.h min/max macro conflict
  - toTiffPath(QString) → short path on Windows, UTF-8 on other platforms
  - toTiffString(QString) → std::string version
