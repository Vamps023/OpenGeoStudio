Phase 3.5: Replace legacy intersection polygon with lane-based junction mesh

This is the final step of Phase 3 — the editor now renders junction geometry
from the lane-based JunctionBuilder instead of the legacy polygon generator.

Store (roadStudioStore.ts):
  - Added junctionResults: JunctionResultData[] and roadGraph: RoadGraphData
  - detectIntersection() now builds a RoadGraph from all roads + intersections,
    finds the junction node, builds LaneNetworks for each connected road,
    and calls buildJunction() to generate the lane-based junction mesh
  - The legacy generateIntersection() is still called for road splitting,
    but its polygon/marking output is no longer rendered when a junction
    mesh exists

RoadViewport.tsx — 3D rendering:
  - New junction mesh rendering section in update3DMeshes():
    - Asphalt mesh from C++ typed arrays (Y/Z swapped for Babylon)
    - Marking mesh for lane stripes
    - Debug stripe lines (when debug mode is on)
  - Legacy generated intersection rendering (polygon, stop lines,
    crosswalks, lane connections) is now gated by hasJunctionMesh:
    skipped when a Phase 3 junction mesh exists for the same intersection

RoadViewport.tsx — 2D rendering:
  - Same gating applied to 2D MapLibre layers:
    polygon, stop lines, crosswalks, and lane connections are skipped
    when a junction mesh exists
  - Intersection center marker is always shown (for selection/identification)

The pipeline is now:
  Road → RoadV2 → LaneNetwork → RoadGraph → LaneGraph → JunctionBuilder → Mesh → Babylon

Legacy generateIntersection() is still called for road splitting (trimming
road endpoints at the junction), but its visual output is replaced by
the lane-based junction mesh. A future cleanup can separate the road-
splitting logic from the polygon generation.
