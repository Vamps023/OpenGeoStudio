Phase 2.8: Road Engine Runtime API — buildRoad()

Introduces the single public API that the editor calls to get
everything from the lane engine in one IPC round-trip.

  Road → roadToV2Auto() → LaneNetwork → RoadMarkNetwork → RoadMesh
                                                              ↓
                                                         RoadBuildResult

The editor no longer needs to call four separate functions. It calls
buildRoad(road) and receives:

  - meshSections: Float32Array/Uint32Array (Babylon-ready buffers)
  - lanes: LaneNetworkData (centerlines, boundaries, samples)
  - markings: RoadMarkNetworkData (marking polylines)
  - adapter: BuildAdapterReport (conversion diagnostics)

C++ Bridge (road_bridge.cpp):
  - roadBuildRoad(road) → RoadBuildResult
  - Serializes MeshSection with typed arrays:
      positions: Float32Array (x,y,z interleaved)
      normals:   Float32Array (nx,ny,nz)
      uvs:       Float32Array (u,v)
      indices:   Uint32Array
  - Serializes LaneNetwork (centerlines, boundaries, sample points)
  - Serializes RoadMarkNetwork (marking polylines with style)
  - Serializes AdapterReport (exact, segments, warnings)

IPC Layer:
  - New channel: ROAD_BUILD_ROAD = 'road:buildRoad'
  - Handler in roadEngineHandler.ts
  - Preload bridge: window.roadEngine.buildRoad(road)
  - TypeScript types in roadEngineClient.ts:
      MeshSectionData, LaneNetworkData, LaneCenterlineData,
      LaneBoundaryData, SamplePointData, RoadMarkNetworkData,
      RoadMarkPolylineData, BuildAdapterReport, RoadBuildResult
  - RoadEngineAPI.buildRoad() + convenience export roadEngine.buildRoad

    - Performance: 1000-segment road < 5s
