Phase 1.3: ArcSegment + curvature sign convention

Implements ArcSegment (task 1.3 of Phase 1 — Geometry Kernel Refactor).
Purely additive — no existing files modified, legacy model untouched.

Design decisions (per user direction):
- Storage: startPoint + startHeading + curvature + arcLength (OpenDRIVE-style)
- NOT center+radius+angles (option b) — that's a view, not storage
- Derived accessors: radius() = 1/|κ|, center() computed from start+heading+κ
  These give geometric intuition without a second source of truth to sync
- Curvature sign: positive = left turn (CCW), matching OpenDRIVE
- Documented curvature convention on GeometrySegment base class header
  so all subclasses (Arc, Spiral, Bezier) follow the same convention

Curvature convention comment added to GeometrySegment:
  Positive curvature = left turn (CCW), matching OpenDRIVE.
  Negative curvature = right turn (CW).
  Also documents the parameterization pattern:
    heading(s) = startHeading + ∫₀ˢ κ(u) du
    position(s) = startPoint + ∫₀˵ [cos(heading(u)), sin(heading(u))] du
  And notes Bezier as the legitimate exception (stores P0-P3, Q2).

ArcSegment implementation:
- evaluateDS: integrates heading linearly, position via circle parametrization
- center(): left normal of startHeading × signed radius
- radius(): 1/|curvature|
- sweepAngle(): curvature × arcLength (signed)
- curvatureDS: constant (returns curvature_ for all s)
- clone(): deep copy via make_unique
