Phase 2.5: Lane Network — persistent lane representation

Introduces the canonical lane network that all downstream subsystems
consume. Generated once from RoadV2, shared by markings, mesh, AI,
OpenDRIVE, and debug overlays.

New file: lane_network.hpp
  Separation of concerns:
    lane_engine.hpp   = Data model
    lane_geometry.hpp = Evaluation (single point)
    lane_sampling.hpp = Sampling (polyline generation)
    lane_network.hpp  = Persistent lane representation (THIS FILE)

  LaneCenterline struct:
    - laneId, type (Driving/Shoulder/Border)
    - startS, endS, length
    - vector<SamplePoint> samples (adaptively sampled)
    - isDrivable(), isCenter/Left/Right()
    - positions() convenience accessor

  LaneBoundary struct:
    - innerLaneId, outerLaneId (which lanes it separates)
    - isRoadEdge (true for outer edge of road)
    - startS, endS, length
    - markType, markColor, markWidth (default markings assigned)
    - vector<SamplePoint> samples
    - id() debug string

  LaneNetwork struct:
    - roadId, totalLength, numLaneSections
    - vector<LaneCenterline> centerlines
    - vector<LaneBoundary> boundaries
    - findCenterline(laneId), findCenterlines(laneId) (multi-section)
    - findBoundaries(innerId, outerId)
    - roadEdges(), centerLines()
    - maxDrivableLanes()

  generateLaneNetwork(road, params):
    - Generates all centerlines and boundaries from RoadV2
    - Handles multi-section roads (separate centerlines per section)
    - Handles legacy roads (synthesized from width/laneCount)
    - Uses adaptive sampling from 2.4
    - Assigns default markings:
      - Center line (adjacent to lane 0): dashed yellow
      - Inner lane boundaries: dashed white
      - Road edges: solid white

  Multi-section handling:
    - Each section generates its own set of centerlines/boundaries
    - Lane 1 in a 2→4 transition produces 2 centerlines
    - Section s-ranges are [startS_i, startS_{i+1})
    - Centerlines at section boundaries are position-continuous
