Add QGIS-style RasterWriter and DemDecoder for proper GeoTIFF export

Studied QGIS source (QgsRasterFileWriter, QgsGdalProvider, QgsGdalUtils)
and adopted their patterns using libtiff directly (no GDAL dependency):

RasterWriter (new):
- Proper GeoKey directory construction for EPSG:4326, EPSG:3857, UTM zones
  (same structure GDAL/libgeotiff builds internally)
- GeoTransform calculation matching QGIS globalOutputParameters pattern:
  [originX, pixelW, 0, originY, 0, -pixelH]
- Compression support (Deflate, LZW, None) matching GDAL creation options
- Nodata value support per band (GDALSetRasterNoDataValue pattern)
- All data types: Float32, Int16, UInt16, Byte (QGIS DataType mapping)
- RGB GeoTIFF (3-band 8-bit) for imagery
- World file generation (.pgw/.tfw/.jgw) matching QGIS layout exporter

DemDecoder (new):
- Terrarium format decoding: (R*256 + G + B/256) - 32768
- Mapbox Terrain-RGB decoding: -10000 + ((R*65536 + G*256 + B) * 0.1)
- AAIGrid (ASCII ArcGrid) parsing for OpenTopography
- GeoTIFF DEM loading for Copernicus/SRTM
- Auto-detection from data magic bytes and source name
- Bilinear resampling to target resolution
- Elevation-to-QImage conversion for visualization

ExportEngine (refactored):
- DEM download now uses DemDecoder for proper elevation decoding
- DEM output uses RasterWriter with format-specific data types:
  Float32 (full precision), Int16 (meters), UInt16 (normalized),
  PNG16+world file, R16 raw+world file
- Imagery output uses RasterWriter: PNG+world file or RGB GeoTIFF
- CRS mode mapping from CrsSource to GeoCrsMode with proper EPSG codes
- Local file loading uses DemDecoder for proper GeoTIFF DEM reading
- Compression option respected throughout export pipeline
