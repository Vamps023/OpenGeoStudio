Phase 1.8.3d: Tool metadata generation + serialization + round-trip

Completes the authoring pipeline: tool → metadata → serialization →
exact reconstruction. Newly created arcs and spirals never enter the
legacy compatibility path.

Changes:
- SegmentKind enum replaces free-form string type (Line, Bezier, Arc, Spiral)
- SegmentMetadata: version field added (schema evolution)
- Road: formatVersion field added (1=legacy, 2=with segmentMeta)
- createCircleArc(): emits SegmentMetadata(kind=Arc) on first CP
  with exact curvature, arcLength, startHeading
- createClothoidArc(): emits SegmentMetadata(kind=Spiral) on first CP
  with exact curvatureStart, curvatureEnd, segmentLength, startHeading
- createSegment(): sets formatVersion=2
- road_adapter.hpp: whole-curve metadata path (Arc/Spiral on CP[0]
  creates a single segment, skipping sampled CPs)
- road_adapter.hpp: exhaustive switch with default case for corrupted data
- road_bridge.cpp: full segmentMeta serialization (parse + output)
  - segmentMetaToJs: serializes metadata to JS object
  - parseSegmentMeta: parses metadata from JS object
  - Old files without segmentMeta → nullopt (legacy adapter path)
  - New files with segmentMeta → exact adapter path

Tests (16 new, 224 total, 1185 assertions):
- Tool metadata emission: arc/clothoid emit metadata on first CP,
  correct parameters, formatVersion=2
- roadToV2 produces ArcSegment/SpiralSegment from tool metadata
  (not LineSegment), exact=true, no warnings
- Round-trip: arc → roadToV2 → centerline matches at endpoints,
  curvature is constant, length matches metadata
- Round-trip: clothoid → roadToV2 → length matches, curvature
  transitions from k0 to k1
- Backward compat: old file (metadata stripped, formatVersion=1)
  uses LineSegments, both adapter paths work
- SegmentKind enum: distinct values, default is Line, all fields
  constructible

All 113 vitest tests remain green (no regression).
Legacy Road path is completely untouched.
