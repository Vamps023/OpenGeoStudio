7 fixture roads:

  2. straight_5pt — 5 corner points, polyline

  4. s_clothoid — Clothoid S-curve (17 CPs)
  5. bezier_arch — 4 points with bezier handles (arch shape)
  6. mixed_line_bezier — Mix of corner and smooth points
  7. tiny_segments — 30 short segments (0.05-0.2m), alternating headings
     (stress-tests cumulative offsets, binary search, FP accumulation)

Golden data format (per sample):
  { s, x, y, heading, curvature }
  - s: cumulative arc length (m)
  - x, y: position (m, local coordinates)
  - heading: direction (rad), computed via finite difference
  - curvature: signed curvature (1/m), computed via 3-point circumcircle
    (positive = left/CCW, matching our convention)

Derived geometry computation:
  The legacy engine only returns {x, y}[] from sampleCenterline().
  Heading: central difference (forward/backward at endpoints).
  Curvature: 3-point circumcircle formula: κ = 2·cross / (|a|·|b|·|c|).
  These are approximations — when RoadV2 produces exact heading/curvature
  from evaluateDS()/curvatureDS(), the parity test will use appropriate
  tolerances.

Test structure:
  - First run (or DELETE_GOLDEN=1): generates and saves golden data
  - Subsequent runs: verifies live engine output matches committed data
  - Per-fixture: metadata, sample count, s monotonicity, position/heading/
    curvature/length match
  - Sanity checks: straight=0 curvature, arc=nonzero curvature, bezier=
    nonzero curvature, tiny_segments=small total length
