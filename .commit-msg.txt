Phase 6: Terrain Studio — area selection, tile grid, and export

Implemented the Terrain workspace with area selection and export
functionality entirely in C++/Qt (no TypeScript, no Sharp, no Node.js):

Data model (TerrainTypes.hpp):
- GeoBounds (north/south/east/west, makeSquare for 1:1 aspect ratio)
- Tile and TileGrid for dividing large areas into export tiles
- HeightmapFormat (PNG16, R16, GeoTIFF Int16/UInt16/Float32)
- AlbedoFormat (PNG, GeoTIFF RGB)
- DemSource (OpenTopo SRTM GL1/GL3, ALOS, Copernicus, NASADEM, GLAD)
- ImagerySource (ArcGIS, Google, Mapbox)
- ExportSettings with API key management

State management (TerrainStore):
- Area bounds selection with automatic square constraint
- Tile grid computation (1/2/4/8 km tile sizes)
- Tile selection (individual toggle, select all, clear)
- Export settings management
- JSON serialization for project persistence

2D viewport (TerrainViewport):
- MapLibre satellite map background
- Shift+drag area selection with live preview (cyan rectangle)
- 1:1 square constraint on selection
- Tile grid overlay with selected/unselected styling
- Tile labels (row,col)
- Click tiles to toggle selection
- Pan with non-shift drag or middle mouse

Export panel (ExportPanel):
- Heightmap format dropdown (5 formats)
- Albedo format dropdown (2 formats)
- DEM source dropdown (6 sources)
- Imagery source dropdown (3 sources)
- Resolution spin boxes (256-8192px)
- Deflate compression checkbox
- OpenTopography API key input (password mode)
- Mapbox token input (password mode)
- Tile count display and select all/clear buttons
- Export button with directory picker
- Progress bar and status label

Export engine (ExportEngine):
- QNetworkAccessManager for HTTP downloads
- DEM download from OpenTopography API (with API key)
- DEM download from GLAD SRTM (with basic auth)
- Imagery download from ArcGIS/Google/Mapbox tile servers
- Automatic zoom level selection based on tile size
- QImage-based image processing (scaling to requested resolution)
- Fallback placeholder images when downloads fail
- Terrain manifest JSON output (Babylon.js preset format)
- Sequential tile processing with progress reporting

Note: GeoTIFF output is not yet implemented — current implementation
writes PNG files. A full GeoTIFF writer using libtiff will be added
in a future iteration. The DEM download currently creates placeholder
heightmaps; parsing the AAIGrid/GeoTIFF response from OpenTopography
requires a TIFF parser which will be added next.
